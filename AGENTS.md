# Project: AI QA Prototype (Python/pytest)

## Stack
- Python 3.11+
- pytest, pytest-playwright, playwright
- pytest-self-healer (auto-repair of Playwright selectors via LLM)
- Groq API (test generation from natural language)
- Ollama qwen2.5-coder:3b (local LLM for self-healing)
- GitHub Actions

## Project Structure
```
.
├── .github/workflows/qa-ai-pipeline.yml
├── tests/
│   ├── test_example.py          # Intentionally broken test (healing demo)
│   ├── test_generated.py        # Generated by Groq
│   └── test_regression.py       # Optional: proves healing is cached
├── scripts/
│   └── generate_test.py         # Groq generation script
├── requirements.txt             # All Python dependencies (single file)
├── .env                         # GROQ_API_KEY (never committed)
├── .gitignore
├── AGENTS.md
└── PROJECT.md
```

## Dependencies
All Python packages are declared in `requirements.txt`. Install with:

```bash
pip install -r requirements.txt
playwright install chromium
```
Do NOT install packages individually with `pip install <package>`; always update `requirements.txt` and re-run `pip install -r requirements.txt`.

## Rules
- All tests use the `healing_page` fixture (NOT the default `page` fixture).
- Every interactive action that supports a `purpose` argument (`click`, `fill`,
  `check`, `select_option`, …) **must** include a descriptive `purpose` string.
- `goto()` does **not** accept `purpose`.
- The default start‑page is **https://example.org/**; use it unless the
  description says otherwise.
- Generated test files must contain **only raw Python code** – no markdown
  fences, no extra comments, no surrounding text.
- Tests must be asynchronous:
  ```python
  @pytest.mark.asyncio
  async def test_…(healing_page):
      …
  ```
- Use selectors that actually exist on https://example.org/ (e.g. the link
  with text “Learn more”; there is no `<h1>` on that page).

## Commands
- Install dependencies: `pip install -r requirements.txt && playwright install chromium`
- Run all tests with healing: `pytest tests/ -v --llm-provider=ollama --ollama-model=qwen2.5-coder:3b`
- Generate a test: `python scripts/generate_test.py "natural language description"`
- Check Ollama model: `ollama list` (must show `qwen2.5-coder:3b`)

## Notes for the Agent
- When writing `tests/test_example.py`, the selector `button#old-submit-id` must be deliberately wrong so healing is triggered.
- When writing `scripts/generate_test.py`, the system prompt sent to Groq must include the Rules section above.
- When writing `.github/workflows/qa-ai-pipeline.yml`, include steps to install Ollama, start it, and pull `qwen2.5-coder:3b` before running pytest.
- If a test fails after healing, inspect `reports/healing_report_*.json` and refine the `purpose` string to be more specific.
